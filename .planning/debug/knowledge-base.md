## e2e-license-spec-rot — 5 real-WKWebView e2e specs rotted (drop-notice heading collision, removed feature, harness ACL gap)
- **Date:** 2026-08-07
- **Error patterns:** Your Pro features turned off, statusHeading, drop notice, licenseDropNoticeAck, Update check failed, updater endpoint, iap-spike, data-testid=iap-spike, could not establish Pro tier, entitlementsOverride full, e2e-spike, WKWebView, WebDriver, capability ACL, updater:default
- **Root cause:** None of the 5 were cert-expiry rot (ce-machine.lic expiring 2026-07-12 was a red herring — no failing spec asserts a valid-cert Licensed state). (1) `helpers.ts statusHeading()` read the FIRST `<h4>` in the Settings dialog, which is the D-84 drop-notice card ("Your Pro features turned off") whenever `licenseDropNoticeAck=false` — set by the first Pro→free transition in the shared WDIO session (appearance.e2e cleanup → store.ts:117) and persisted for the rest of the run. (2) iap-spike.e2e tested a temporary dev block removed in Phase 28-05. (3) ship-gate Cases 4/5 failed second-order because license.e2e leaves `entitlementsOverride="full"` in prefs and resolve.ts honors that override ABOVE license_status, so a seeded corrupt cert could not drop entitlements. (4) settings.e2e "Update check failed" was a HARNESS gap: `scripts/e2e-spike.sh` ran the BASE tauri config, but `updater:default` lives only in `src-tauri/tauri.direct.conf.json` (kept out of `capabilities/default.json` so the appstore capability codegen doesn't fail on a compiled-out plugin) — so every `plugin:updater|*` invoke was ACL-DENIED under an ACL no shipped channel uses.
- **Fix:** Test/harness-side only, no product bug. `statusHeading()` skips the drop-notice heading (regex on collapsed whitespace, not exact match); ship-gate `beforeEach` clears the leaked override via `resetPrefsBlob()` + `browser.refresh()` (the usePreferences singleton keeps a stale in-memory copy, so a disk-only wipe is re-persisted); obsolete iap-spike spec + screenshot deleted; `tauri:dev:e2e` now runs `VITE_CHANNEL=direct tauri dev --features webdriver --config src-tauri/tauri.direct.conf.json` so the gate exercises the shipped direct-channel capability set; the updater assertion accepts three outcomes and tolerates "Update check failed" ONLY when a runner-side probe classifies the endpoint `unreachable` (three-verdict classifier — healthy / misconfigured / unreachable — after a Codex finding that a boolean "reachable" laundered 404s, bad URLs and schema-broken latest.json into "external outage"; the transport walk must descend `AggregateError.errors`, not just `cause`).
- **Files changed:** test/e2e/helpers.ts, test/e2e/settings.e2e.ts, test/e2e/ship-gate.e2e.ts, test/e2e/license-states.e2e.ts, test/e2e/iap-spike.e2e.ts (deleted), test/e2e/__screenshots__/iap-spike-no-op-arm.png (deleted), package.json, scripts/e2e-spike.sh, docs/appstore/PHASE-26-SANDBOX-WALKTHROUGH.md
