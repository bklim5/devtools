# Phase 28 — UI Design Contract

> Visual and interaction contract for the Entitlement-Source Swap + Store License Pane phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a REUSE phase, not a redesign.** The `appstore` build variant swaps three existing surfaces — License pane, Upsell modal, Updates pane — for App-Store-managed equivalents (Buy + Restore, no Keygen concepts). Every token, class, banner and interaction below is lifted VERBATIM from already-shipped components (`LicenseSettings.tsx`, `UpsellPanel.tsx`, `UpdatesSettings.tsx`) and the canonical `design/DevTools Mockup.html` → `src/index.css` `@theme`. **The only net-new design is copy** (App-Store-managed wording per D-14) and the SUBTRACTION of Keygen affordances. No new visual system, no new sizes, no new tokens, no new buttons.
>
> All visual/interaction/copy decisions are pre-populated from CONTEXT.md D-01..D-15 (binding) + the existing component source. shadcn gate is N/A (no shadcn; "zero new webview runtime/dev deps" is a binding project constraint). No open design questions block this contract.

## Spacing Scale

8-point scale, inherited verbatim from the existing components. No phase-specific values introduced.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), pill padding (`px-2 py-0.5`) |
| sm | 8px | Button-row + banner-content gaps (`gap-2`) |
| md | 16px | Card inner gap (`gap-4`), pane section gap (`gap-4`) |
| lg | 24px | Card inner padding (`p-6`); banner padding is 20px (`p-5`) — the existing banner value |
| xl | 32px | Pane outer padding (`p-8`) — matches `LicenseSettings`/`UpdatesSettings` |
| 2xl | 48px | Vertical break between the free-state status and the inline upsell (`gap-12`) — existing free-pane rhythm |
| 3xl | 64px | Reserved — not expected on these single-column panes |

Exceptions:
- Banner padding is **20px (`p-5`)**, not 24px — this is the existing `LicenseSettings` Pro-active / attention-banner value, reused verbatim (D-11). Do NOT normalize it to 24px.
- Pane outer padding is **32px (`p-8`)** — the existing pane shell value.
- Store-surface buttons keep the existing `px-3 py-1` (12px / 4px) — do not introduce a new button size.
- Focus/touch targets ≥ 24×24px (WCAG 2.5.8), inherited from the shipped buttons.

|------|------|--------|-------------|-------|

| Banner / card heading | 16px | 600 | 1.2 | Status banner + drop-notice + upsell-success headings — `HEADING_CLASS` (`text-[16px] font-semibold leading-[1.2] text-tx`) |
| Pitch title (upsell only) | 24px | 600 | 1.2 | The `StoreUpsell` hero pitch heading — `PITCH_TITLE_CLASS` (`text-[24px] font-semibold leading-[1.2] text-tx`), reused from the existing pitch |
| Updates version line | 15px | 600 | default | "TinkerDev v{n}" running-version readout — `text-[15px] font-semibold text-tx` (existing `UpdatesSettings` value, KEPT — D-13) |

## Color

60/30/10 split inherited verbatim from `src/index.css` `@theme`. Accent stays **selection / primary-action only** (app-wide discipline D-24): status glyphs are NEVER accent. **The store surfaces use the green `ok` token for the Pro-active banner and NEVER the amber `warn`/`bad` tokens** — StoreKit has no attention/refresh-needed/problem states (D-11), so there are ZERO amber/red states in the store License pane.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-pane` `#14161b` (dark) / `#ffffff` (light) | Pane background |
| Secondary (30%) | `--color-panel` `#181b21` / `#f7f8fa`; `--color-input-bg` | Cards, banners, details table, disabled-button surface |
| Accent (10%) | `--color-accent` `#5b9bf8` / `#1763d6` (+ `accent-soft` fill, `accent-line` border, `ring`) | See reserved list below |
| Semantic — OK | `--color-ok` `#34d399` / `#15722f` (+ `ok-soft` fill, `ok-line` border) | The Pro-active banner ONLY — green dot + green "Pro" pill + soft-fill banner. Calm, not celebratory |
| Semantic — Attention/Destructive | `--color-warn` / `--color-bad` | **NOT USED in any store surface.** No amber attention banner, no red destructive button (there is no Deactivate in the store build — D-11). These tokens MUST NOT appear in `StoreLicenseSettings`/`StoreUpsell`/store-Updates |

Accent reserved for (explicit — never "all interactive elements"):
1. The **Buy primary CTA** fill/border — `PRIMARY_BTN_CLASS` (`border-accent-line bg-accent-soft text-accent`) on the Free-state Buy and the `StoreUpsell` Buy.
2. The **upsell pitch medallion + feature icons** — `bg-accent-soft` tiles with `text-accent` glyphs (existing pitch treatment, reused).
3. **`focus-visible` rings** on every interactive control (`focus-visible:ring-2 focus-visible:ring-accent`) — mandatory, WCAG-AA.

Everything else is **neutral** (`tx`/`tx-2`/`tx-3`/`bd`/`bd-2`): the Restore secondary button (`SECONDARY_BTN_CLASS`), the running-version readout, the "managed by the App Store" line, the drop-notice, all status/helper copy. Calm tone is binding: **no toasts, no spinners, no opacity-only state**. In-flight + result feedback is a calm `aria-live="polite"` text line (the `IapSpikeBlock` readout pattern — D-15), never spinner chrome.

## Interaction & Layout Contract (phase-specific)

Binding contracts the executor implements and the checker/auditor verify:

- **Static variant switch, separate modules (D-01).** `settingsPanes.tsx` + the upsell opener pick `Store*` components behind `IS_APPSTORE` (build-time, tree-shakeable). NOT an `if (IS_APPSTORE)` inside the existing components — that would leave Keygen strings in the bundle and fail the D-03 grep gate.
- **Two mutually-exclusive License layouts, one at a time (D-11).** Pro-active (green banner + always-visible Restore) XOR Free (status + Buy + Restore). The gate state (`refreshEntitlements()` → `isPro`) selects; no third/attention layout exists.
- **Restore is ALWAYS reachable (D-10, Apple expectation).** Shown in BOTH License layouts AND on `StoreUpsell` next to Buy.
- **Live unlock + live drop, no relaunch (D-06).** A single store-build boot listener `platform.iap.onPurchaseUpdated(() => refreshEntitlements())`; purchase → Pro live, refund/revoke → Pro drops live (+ drop-notice). Buy/Restore handlers also call `refreshEntitlements()`. Calm flip — no toast, no restart (the proven live-flip path).
- **Passive boot read, never silent restore (D-08/D-09).** Boot calls `iap.currentEntitlements()` (local cache read, NO Apple-ID prompt). The explicit **Restore Purchases** button is the ONLY thing that calls `iap.restore()` (`AppStore.sync`, MAY prompt auth).
- **Calm `aria-live="polite"` feedback, no spinners (D-15 pattern).** ONE readout region per surface carries in-flight + result strings as plain text. A no-op/error arm renders the calm "App Store isn't available" line — never a red banner, never an uncaught throw, never a white screen.
- **Keyboard-reachable + WCAG-AA (mandatory).** Every Buy/Restore/dismiss control is a native `<button>` Tab stop with `focus-visible:ring-2 focus-visible:ring-accent`. `StoreUpsell` reuses the `UpsellModal` focus-trap + Esc + return-focus contract verbatim.
- **Layout-agnostic, responsive Tailwind (binding constraint).** `w-full`, no fixed widths; banners/cards reuse the existing `max-w-[420px]` measure where the License pane already uses it. Self-hosted fonts, no runtime network.
- **Grep-clean depends on tree-shaking (D-03 caveat).** A stray non-static import that re-pulls `licenseUi`/`UpsellPanel` keeps Keygen strings in the store bundle. Verified on the SIGNED bundle by the extended `verify-appstore-bundle.sh` forbidden-string grep (`license.tinkerdev.io`, `BUY_LICENSE_URL`, `$9`, key-field markers).
