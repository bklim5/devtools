3. Add a genuine `--build-only` (no-publish) mode to the direct release driver. Today `build-and-publish.mjs` has exactly TWO modes: `--dry-run` short-circuits BEFORE `tauri build` (proves nothing about the real build), and the normal path runs the IRREVERSIBLE tail (build → sign → notarise+staple → spctl → write `latest.json` → `gh release create` → `gh release upload`). There is no flag that runs the real build but stops before publish — so the MAS-SHIP-05 real-DMG proof was previously NOT executable without either testing the wrong path (`tauri:build:direct`, which skips the driver's notarise/staple/spctl gate) or cutting a real public release. `--build-only` runs the read-only preflights (incl. gh auth/permission/release-view) and the full build+sign+notarise+staple+spctl, then RETURNs exit 0 BEFORE any publish side-effect — no `latest.json` write, no `gh release create`, no `gh release upload`. (The read-only preflight `gh` probes DO run on this path, and that is intentionally fine — only the publish WRITES must be unreachable.) Parse it in the pure `parsePublishArgs` (unit-tested), make it mutually exclusive with `--dry-run`, and add a `release:build-only` package.json script.
4. Prove the direct DMG channel is un-regressed (MAS-SHIP-05) the way CONTEXT.md line 39 LOCKED it: `release:publish --dry-run` preflights (cheap) PLUS a REAL local universal DMG build + sign + notarise + staple via `pnpm release:build-only` WITH NO `gh release` and NO tag — proving the path actually builds/signs/notarises after all the Phase 26–29 variant work — and assert `decoder.ts` + its 19 tests are byte-for-byte untouched.

Tasks 1–3 are autonomous (config/artifact, the driver code-change + its unit test, and the cheap dry-run preflight).
