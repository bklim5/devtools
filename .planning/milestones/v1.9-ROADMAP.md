## Milestone Summary

**Delivered:** two new wedge-gated formatter tools — the **12th** (HTML prettifier) and **13th** (combined JS/TS/JSX/TSX prettifier, no language picker) — each of which **Prettifies** (Prettier 3.8.3 standalone, byte-identical to CLI `prettier --write`, HTML incl. embedded `<script>`/`<style>` parity) AND **Minifies** (esbuild-wasm 0.28.0 for JS/TS/JSX/TSX + CSS; a pure offline `minifyHtml` for HTML). Both heavy engines are vendored/self-hosted (no CDN), lazy-loaded and code-split — proven never initially-reachable from the entry chunk by an ungated Vite build guard (`prettierChunkGuard.mjs`) with a non-vacuous self-test, sentinel-FATAL-wired into `verify-appstore-bundle.sh`. The shared async seam is `useAsyncFormat` (180ms debounce + monotonic-reqId latest-wins + pending) with a default-on 2 MB UTF-8 DoS guard (bounded counter, never full-encodes oversize input). `FormatterView` was generalized to a mutually-exclusive `[Prettify|Minify]` mode selector + optional printWidth across ALL FOUR formatter tools (JSON/XML retrofitted, pure transforms unchanged), plus Prettify-gated Semi/Single-quotes toggles for JS/TS. Golden parity locks RED-on-drift (HTML script+style fixture, four JS/TS dialects at named parsers, `formatJsTs` routing goldens + a proven-live babel-fallback fixture); fallback chains (`formatJsTs` typescript→babel, `minifyJsTs` tsx→ts) are routing-locked by injectable-runner ORDER tests. `decoder.ts` + its 19 tests stayed byte-for-byte untouched throughout; both build channels (direct + appstore) rebuilt fresh universal at HEAD.

**Key decisions:**
- **Two scoped heavy-dep exceptions accepted** — the v1.9 research recommended DROPPING Minify (Prettier cannot minify); the user overrode it and KEPT a Minify button on both tools, so v1.9 accepts TWO deliberate, scoped, reviewed heavy runtime deps (Prettier for prettify + esbuild for minify) — both vendored/offline/lazy, NOT a precedent for grab-bag deps.
- **D-05 JSON/XML retrofit to the unified mode selector** — the earlier "no change to existing JSON/XML behaviour" was superseded: JSON and XML were retrofitted to the shared `[Prettify|Minify]` mode selector and re-verified, while their pure transform logic (`json.ts`/`xml.ts`) and tests stayed unchanged (only UI/control wiring changed; engines stay per-tool).
- **A 2 MB input size cap, not a Web Worker** — Prettier/esbuild are ~linear (no catastrophic-backtracking freeze class), so a shared main-thread size guard in `useAsyncFormat` handles pathological pastes; a worker would fragment the lazy chunks / risk duplicating the heavy engines.
- **Option A JSX-factory minify semantics** (34-05, human-ratified 2026-07-06) — under esbuild preserve-mode minify, unused JSX factory bindings are dropped; accepted as correct for the modern automatic runtime (NO code change, NO rebuild).
- **Packaged CSP `wasm-unsafe-eval`** — the packaged `.app` CSP `script-src 'self'` blocked esbuild WASM; dev CSP is permissive so e2e/unit missed it (a packaged-only class). Fixed by adding `wasm-unsafe-eval` to the base tauri.conf.json CSP, verified on the binary.
