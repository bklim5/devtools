- BAD-EMBEDDED-`<script>` (code error, Minify): `minifyHtml("<script>function(</script>")` runs the body through esbuild, which throws a JS syntax error mapped through `offsetToLineCol` → surfaces as `<script> block: …` with a line:col. Assert the strongest available shape: a line:col `/\d+:\d+/` somewhere in the error text.
  · EXECUTOR FALLBACK (this category only): if at execution the esbuild-mapped error for this specific input surfaces WITHOUT a col, downgrade THIS assertion to line-located (`/\bline \d+/` or `/\d+:/`) AND record the observed per-category mapping in both `<engine_error_facts>` (update this block) and `33-04-OFFLINE-PROOF.md`. Do NOT downgrade the MALFORMED-HTML category — its col is confirmed. Never accept a line-only match for a case where the col is available.
- CAVEAT (why the split is required): a broken embedded `<script>` does NOT error under `formatHtml` — Prettier's embedded formatting is BEST-EFFORT and leaves the raw script rather than throwing (e.g. `<script>const x=</script>` and `<script>function(</script>` are BOTH ACCEPTED by `formatHtml`). So the embedded-code category MUST be proven via Minify/esbuild, and the HTML-structure category via Prettify/html-parser. Do NOT assert a Prettify error on a broken embedded script (the html parser accepts it — the test would assert the wrong thing).
