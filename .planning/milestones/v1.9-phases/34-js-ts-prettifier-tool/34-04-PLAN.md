## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pasted code → useAsyncFormat → Prettier/esbuild | Untrusted multi-MB paste can flood the main-thread engines / re-encode / re-trim at the tool seam |
| derived output → clipboard | Output text written to the OS clipboard via the platform seam |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-08 | Denial of Service | multi-MB paste freezing the UI (SC5 carry-forward) | mitigate | The tool omits the 4th useAsyncFormat arg → inherits the shared 2 MB bounded guard; an over-cap paste short-circuits to "Input too large" BEFORE the engine and BEFORE any full-string encode/trim. Unit-proven by the cloned SC6 0-encode (identity spy) + no-re-trim (trim spy) tests over ASCII + multibyte + malformed-surrogate + all-whitespace inputs. |
| T-34-09 | Denial of Service | tool-seam re-encode/re-trim reopening the guarded DoS | mitigate | byteCount = hook `inputBytes` (never `byteLen(input)`); emptiness = hook `isEmpty` (never `input.trim()`); enforced by source scope-guard greps in the acceptance criteria (33-HARNESS-REMEDIATION rules). |
| T-34-10 | Tampering | malformed paste crashing the mounted tool | mitigate | formatJsTs/minifyJsTs return error-as-value; the tool renders a calm role=alert line:col via conciseError and clears output; recovery-on-next-valid-paste is unit-proven (never a crash). |
| T-34-11 | Information Disclosure | output text to clipboard | accept | Copy writes only the user's own derived output through the existing platform clipboard seam (no new surface; identical to every other formatter tool). |
| T-34-12 | Spoofing | non-JS `<script>` data blocks / bundling via esbuild | mitigate | minifyJsTs uses esbuild `transform` (single-file, NEVER `build`/bundle — Out of Scope); no import resolution or network. |
</threat_model>
