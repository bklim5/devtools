    ```typescript
     * common case (D-03). Empty input is handled by the composed formatScript.
     */
    export async function formatJsTs(
      input: string,
      opts: PrettierFormatOptions,
      // Test-only injection seam for the ORDER proof (default = the real
      // formatScript, so every caller stays two-arg — additive, no caller edits).
      // formatJsTs calls formatScript INTRA-MODULE, so a vi.spyOn on the module
      // export would NOT intercept the internal call; the injected runner does.
      run: (
        input: string,
        lang: ScriptLang,
        opts: PrettierFormatOptions,
      ) => Promise<FormatResult> = formatScript,
    ): Promise<FormatResult> {
      const primary = await run(input, "typescript", opts);
      if (primary.ok) return primary;
      const fallback = await run(input, "babel", opts);
      return fallback.ok ? fallback : primary; // first-attempt error on total failure
    }
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pasted code → Prettier/esbuild parsers | Untrusted arbitrary source text crosses into two heavy parsers on the webview main thread |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01 | Denial of Service | formatJsTs / minifyJsTs run the parser TWICE on malformed input | mitigate | The fallback only fires on the ERROR path (primary `!ok`); both engines are ~linear and the shared `useAsyncFormat` 2 MB cap (inherited free by the tool, Plan 34-04) bounds total input BEFORE either engine runs, so the doubled work is bounded (≤2 parses of ≤2 MB). No unbounded retry loop (exactly one fallback). |
| T-34-02 | Denial of Service | pathological/pathological-regex source to esbuild/Prettier | accept | esbuild/Prettier lexers are not the catastrophic-backtracking class the regex tool guards against (REQUIREMENTS Out-of-Scope: "no catastrophic-backtracking freeze class"); the 2 MB size cap is the accepted mitigation for pathological pastes. |
| T-34-03 | Tampering | malformed paste crashes the engine mid-parse | mitigate | Both new functions compose functions that already wrap the engine in try/catch and return `FormatResult` error-as-value (never a throw past the wrapper); formatJsTs/minifyJsTs only inspect `.ok` and never re-throw. |
| T-34-07 | Tampering | formatJsTs/minifyJsTs silently mis-route (babel-first / ts-loader-first) yet emit byte-identical output for common inputs, so BOTH the unit goldens and 34-02's parity goldens stay green | mitigate | The injectable-runner ORDER unit tests in THIS plan record the actual attempt order and assert typescript-before-babel / tsx-before-ts; a mis-routed impl REDs here even though no byte comparison (unit or 34-02 parity) can distinguish it. This is the load-bearing routing proof — the byte goldens are drift locks only. |
</threat_model>
