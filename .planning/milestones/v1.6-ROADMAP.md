## Phase Details

### Phase 18: Entitlements Seam & Central Gate
**Goal**: Feature gating exists as one central, testable seam — tools and app-level features resolve entitlements through a single gate, locked features stay visible-but-locked, and the registry is lazified — while the in-Tauri default keeps everything unlocked until licensing lands (flipped at Phase 21).
**Requirements**: ENT-01..05
**Plans** (4/4): entitlements core seam + env-split resolver + UpsellPanel; lazy registry (11 loaders) + ToolRoute gate + decoder-isolation proof; lock UX surfaces + DEV free-tier toggle; D-18 doc reconciliation + real-WKWebView e2e + human walkthrough.

### Phase 19: License Activation & Offline Verification
**Goal**: A user with a license key can activate this Mac once online and thereafter launch fully licensed, fully offline — all verification and key material Rust-owned, never in the webview.
**Depends on**: Phase 18
**Requirements**: LIC-01/02/03/04/06
**Plans** (4/4): local Keygen CE bring-up + D-42 SPIKE (key→token denial recorded, real fixtures); pure Rust license core (HMAC fingerprint, fail-closed Ed25519 verify, atomic store, trait-mocked Keychain); Keygen HTTP client + activation state machine + 4 Tauri commands + seam stubs; activation UX in the shared upsell panel + e2e + walkthrough vs live CE.

### Phase 20: Purchase Pipeline
**Goal**: A buyer can pay once through a merchant-of-record checkout and automatically receive a working license key by email — no manual fulfillment, no privileged credentials near the app.
**Depends on**: Phase 18 (parallel-capable with Phase 19)
**Requirements**: PAY-01/02/03
**Plans** (3/3): Buy-CTA opener seam + config.rs prod/dev switch + Buy e2e; TS/Node webhook backend (LS order_created verify + idempotent Keygen create + Resend email); production CE bring-up (Caddy + webhook container + RUNBOOK) + live purchase proven 2026-06-17 (order 8722394).

### Phase 21: License Lifecycle & Ship Gate
**Goal**: The license behaves correctly across its whole lifetime — opportunistic refresh, self-serve transfer, revocation propagation, status UI — the free-tier default flips live, and the full 8-case ship-gate matrix passes end-to-end on a real build.
**Depends on**: Phase 19 + Phase 20
**Requirements**: LIC-05/07/08/09
**Plans** (5/5): expiry-aware resolve_status (OfflineGrace + RefreshNeeded); background refresh scheduler + 5-state TS payload; transfer/revocation surface (webhook email-embed + maskedKey + seat-release helper); live free-tier flip + status route + confirm-first deactivate + e2e; 8-case ship-gate matrix on a fresh prod build (live cases 1/2/7/8 passed vs prod CE).

## Milestone Summary

**Delivered:** A complete one-time-payment lifetime-license system — MoR checkout → webhook → Keygen license → emailed key → in-app paste-activation (HMAC fingerprint, one machine) → offline Ed25519-verified `machine.lic` (~30-day TTL) thereafter, with self-serve transfer + revocation propagation, all behind a central frontend entitlement gate (free keeps all 11 tools; Pro unlocks customization). Proven live end-to-end against prod CE `license.tinkerdev.io` (real purchase order 8722394, ship-gate cases 1/2/7/8).

**Key decisions:** Keygen perpetual + node-locked (`maxMachines=1`); license key in Keychain (Rust-owned, never in JS); webview gating accepted as UX-gating, not DRM; "no network at runtime" gained a narrow licensing-only exception (activation + opportunistic TTL refresh, never per-launch); D-18 pivot — all tools free, customization is the Pro line.

**Constraints held:** decoder.ts + its 19 tests byte-for-byte untouched; zero new webview runtime deps (Rust licensing crates expected/allowed); HashRouter; WCAG-AA; real-WKWebView gate per phase.
