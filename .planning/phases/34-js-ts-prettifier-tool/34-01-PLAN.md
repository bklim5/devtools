<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pasted code → Prettier/esbuild parsers | Untrusted arbitrary source text crosses into two heavy parsers on the webview main thread |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01 | Denial of Service | formatJsTs / minifyJsTs run the parser TWICE on malformed input | mitigate | The fallback only fires on the ERROR path (primary `!ok`); both engines are ~linear and the shared `useAsyncFormat` 2 MB cap (inherited free by the tool, Plan 34-04) bounds total input BEFORE either engine runs, so the doubled work is bounded (≤2 parses of ≤2 MB). No unbounded retry loop (exactly one fallback). |
| T-34-02 | Denial of Service | pathological/pathological-regex source to esbuild/Prettier | accept | esbuild/Prettier lexers are not the catastrophic-backtracking class the regex tool guards against (REQUIREMENTS Out-of-Scope: "no catastrophic-backtracking freeze class"); the 2 MB size cap is the accepted mitigation for pathological pastes. |
| T-34-03 | Tampering | malformed paste crashes the engine mid-parse | mitigate | Both new functions compose functions that already wrap the engine in try/catch and return `FormatResult` error-as-value (never a throw past the wrapper); formatJsTs/minifyJsTs only inspect `.ok` and never re-throw. |
</threat_model>
