**What the chunk-module guard proves — and what it deliberately does NOT (iteration 3 scope-down).** A prior plan revision proposed a `menu://check-updates` STRING grep over the dist — that is a false-GREEN (per `keygen-compileout-d04-proof`: a string grep would not catch surviving `useUpdater`/`update.ts`/`UpdateBanner`/`UpdaterOverlay` JS if the overlay leaked via a stray static import that minified away the literal). The load-bearing proof is the SAME chunk-MODULE inventory the existing licenseUi guard uses: extend `licenseUiFoldInGuard.mjs` to ALSO inventory the updater **UI** module IDs and emit them into the sentinel; assert `updaterInChunks:false` on the signed bundle. **The guard does NOT assert `@tauri-apps/plugin-updater` package absence** — that token is unsatisfiable and inconsistent with the phase's own decisions: `tauri.ts` imports `@tauri-apps/plugin-updater` at TOP LEVEL (line 21) and `index.ts` loads `tauri.ts` via a single dynamic `import("./tauri")` (the one shared platform chunk BOTH builds load via `initPlatform()`), so the inert plugin-updater JS rides along in the shared seam regardless of the overlay extraction. **This is the exact same situation D-05 already ACCEPTS for `plugin-autostart`** (tauri.ts line 26 — D-05 is a runtime NO-OP, not a bundle removal): inert plugin JS in the shared seam is an already-accepted project decision; the safety is proven by NEVER INVOKING it (the 29-02 runtime no-invoke assertion: `platform.updater.check` called 0 times on the store boot path), not by excluding it from the bundle. Requiring plugin-updater absence would FALSE-RED every real store build and contradict D-05. So the load-bearing proof of "updater gone from the store build" is two-part: (1) the updater **UI** modules absent from the store chunks (the overlay extraction genuinely achieves this) + (2) the 29-02 runtime `platform.updater.check === 0` boot-path assertion — mirroring `keygen-compileout-d04-proof` where string/package presence is insufficient and the runtime no-invoke proof is load-bearing.
