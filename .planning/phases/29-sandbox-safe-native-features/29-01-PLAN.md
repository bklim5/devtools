<objective>
Compile the entire Keygen/keyring license Rust surface OUT of the App Store build by gating it behind the default-enabled `direct` Cargo feature, and make `keyring` an optional crate carried only by that feature. The store binary must link no `keyring`, register no license commands, run no Keychain access — the smallest sandbox surface and the strongest MAS-NATIVE-03 guarantee (no `MissingEntitlement`, no unjustified `keychain-access-groups`).

ALSO: gate the tray "Check for Updates…" item OUT of the store build. The updater plugin is already `direct`-only (lib.rs:82-84), so the store binary registers no updater command — but the tray "Check for Updates…" item is currently UNCONDITIONAL (lib.rs:241-247) and its menu-event arm emits `menu://check-updates` (lib.rs:264-266), which the frontend wires to `platform.updater.check()` → a runtime error on a KEPT surface (the tray) when a store user clicks it. This is MAS-NATIVE-02 (the kept tray must work cleanly under sandbox) + the runtime-error half of MAS-NATIVE-03. This is NOT the updater backend (out Phase 27) — it is the surviving tray item Phase 27/28 left intact.

This is D-01 + D-02 (+ the tray-updater hardening folded into Phase 29). The HARD part is NOT the keyring crate — it is making the store binary still COMPILE with `mod license` gated out: every reference to license types/commands outside the module (the `LicenseState` setup, the background-refresh task, the four `invoke_handler` arms) must be `direct`-gated in lockstep. The tray edit has its own compile trap: the `check_updates_i` slot in the `Menu::with_items` slice must be conditionally present so the slice is valid under BOTH feature sets.

Purpose: store Pro state comes ONLY from StoreKit (Phase 28 `baseFromStoreKit`); the Keygen Rust surface is dead weight + an unjustified attack surface in the store build; and the tray must not offer an affordance that throws at runtime.
Output: a `direct`-gated `license` module; an optional `keyring` dep; a 2×2 (debug × appstore) invoke_handler matrix where the appstore arms carry no license commands; a `direct`-gated tray "Check for Updates…" item so the store tray is exactly Show / Settings… / Quit.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| signed store binary → macOS Sandbox/AMFI | the store .app declares entitlements; an unjustified Keychain-group entitlement or a runtime Keychain access under sandbox triggers MissingEntitlement / a security review flag |
| compiled-out code → shipped binary | code gated behind a cfg must be GENUINELY absent from the appstore Mach-O, not merely unreachable |
| tray menu → frontend updater seam | a tray item emits an event the webview wires to a native command; if the command is compiled out (updater) the click drives an invoke against an unregistered command = a runtime error on a kept surface |
