<objective>
Compile the entire Keygen/keyring license Rust surface OUT of the App Store build by gating it behind the default-enabled `direct` Cargo feature, and make `keyring` an optional crate carried only by that feature. The store binary must link no `keyring`, register no license commands, run no Keychain access — the smallest sandbox surface and the strongest MAS-NATIVE-03 guarantee (no `MissingEntitlement`, no unjustified `keychain-access-groups`).

This is D-01 + D-02. The HARD part is NOT the keyring crate — it is making the store binary still COMPILE with `mod license` gated out: every reference to license types/commands outside the module (the `LicenseState` setup, the background-refresh task, the four `invoke_handler` arms) must be `direct`-gated in lockstep.

Purpose: store Pro state comes ONLY from StoreKit (Phase 28 `baseFromStoreKit`); the Keygen Rust surface is dead weight + an unjustified attack surface in the store build.
Output: a `direct`-gated `license` module; an optional `keyring` dep; a 2×2 (debug × appstore) invoke_handler matrix where the appstore arms carry no license commands.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| signed store binary → macOS Sandbox/AMFI | the store .app declares entitlements; an unjustified Keychain-group entitlement or a runtime Keychain access under sandbox triggers MissingEntitlement / a security review flag |
| compiled-out code → shipped binary | code gated behind a cfg must be GENUINELY absent from the appstore Mach-O, not merely unreachable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-01 | Information Disclosure | keyring/MacKeychain linked into the store binary | mitigate | `keyring` is `optional` + listed only under `direct`; `cargo tree --no-default-features --features appstore \| grep keyring` = 0 (Task 1 acceptance). The crate + its Keychain FFI are absent from the store Mach-O, not string-hidden. |
| T-29-02 | Elevation of Privilege | unjustified keychain-access-groups entitlement | mitigate | With no keyring linked and no Keychain access, the store build needs no Keychain entitlement; `entitlements.appstore.plist` carries app-sandbox + network.client + application-identifier ONLY. Audited on the SIGNED bundle in Plan 29-03 (`codesign -d --entitlements`, NO keychain-access-groups). |
| T-29-03 | Denial of Service | store binary registering an unregistered license command → runtime invoke reject | mitigate | The appstore invoke_handler arms register ONLY iap commands (Task 2); the store frontend never calls `platform.license.*` (proven in Plan 29-02's boot-path no-license-IPC assertion). No license command is registered AND none is called. |
| T-29-04 | Tampering | a future edit re-links keyring/license onto the appstore tree | mitigate | Plan 29-03 extends `verify-appstore-bundle.sh` with a FATAL `cargo tree --no-default-features --features appstore \| grep -E 'keyring'` assertion at the gate. |
