The store build has no autostart plugin (compiled out Phase 27), no license commands (Plan 29-01 Task 2), and no updater command (compiled out Phase 27; the surviving tray item gated out in Plan 29-01 Task 3). On the frontend the updater wiring survived: `App.tsx` registers a `menu://check-updates` listener that calls `platform.updater.check()` and a launch auto-check that does the same — both would invoke the unregistered updater command in the store build and throw. With launch-at-login absent there is no call path to the autostart plugin — D-05 hardens it. The D-03 assertion proves the shared `tauri.ts` license/updater IPC literals (which ride along in the bundle because the `iap` arm imports the whole `tauriPlatform` object) are NEVER invoked in the store boot path.

Purpose: MAS-NATIVE-04 (launch-at-login hidden/absent) + the runtime-safety half of MAS-NATIVE-03 (no unregistered-command invoke at boot) + MAS-NATIVE-02 (the kept tray's frontend wiring must not drive a compiled-out command).
Output: an `IS_APPSTORE`-gated General pane; an `IS_APPSTORE` no-op autostart seam; `!IS_APPSTORE`-gated updater listener + launch-auto-check effects; a boot-path no-license-IPC + no-updater-IPC test.
