<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| StoreKit transaction → Rust grant core | An attacker-influenced/tampered transaction crosses into the entitlement decision; verification status is the only trust signal. |
| iap_* command return → JS seam | The granted entitlement codes cross to the webview; an over-grant here unlocks Pro for free. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-01 | Elevation/Spoofing | `grant_from_outcome` / `granted_entitlements` | mitigate | FAIL CLOSED: only `Purchased(Verified)` returns pro codes; `Unverified`/`Cancelled`/`Pending` return `[]`. Unit-tested (Task 2) — this is MAS-IAP-04's acceptance criterion. |
| T-26-02 | Elevation | `intersect_pro` | mitigate | Intersect granted codes with `PRO_ENTITLEMENTS` (= ALL_ENTITLEMENTS) so a forged/unexpected code can never unlock more than the two real pro entitlements. Mirrors `baseFromLicense` T-21-12. Unit-tested. |
| T-26-03 | Tampering | direct (non-appstore) build | mitigate | The whole iap module + commands are `#[cfg(feature = "appstore")]`; `cargo tree` without the feature excludes the plugin and `cargo build` (default) compiles no iap arm — verified in acceptance criteria. |
| T-26-04 | Information Disclosure | iap command bodies | accept (this plan) | Spike command bodies are deterministic stubs with no network; the real serverless-verify proof (no outbound beyond Apple) is Plan 05/06's `log stream` human check. No secret handled here. |
</threat_model>
