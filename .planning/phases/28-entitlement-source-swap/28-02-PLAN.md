PLUGIN listener mechanism (tauri-plugin-iap@0.9.1, VERIFIED from crate source):
- The plugin's macOS `handleTransactionUpdate` calls `trigger("purchaseUpdated", jsonString)` on EVERY verified background transaction (IapPlugin.swift:290) incl. refund/revoke.
- `trigger` routes to the plugin's `pub(crate) mod listeners` registry — NOT reachable from our crate (pub(crate)).
- The ONLY public path to subscribe is the IPC command `register_listener(event: String, handler: tauri::ipc::Channel<serde_json::Value>)`, exposed as `plugin:iap|register_listener`.
- Granular permission EXISTS: `iap:allow-register-listener` (permissions/autogenerated/commands/register_listener.toml) — grants ONLY that command, NOT purchase/restore/acknowledge/consume. This is the Phase-26-safe permission (the broad `iap:default` is FORBIDDEN — it would expose raw purchase IPC, BRIDGE-VIABILITY §SECURITY CORRECTION).
- The event name the plugin triggers is the literal string "purchaseUpdated".

DECISION — bridge shape: the cleanest Phase-26-respecting wiring is to register the listener Channel FROM THE WEBVIEW (tauri.ts) via `invoke("plugin:iap|register_listener", { event: "purchaseUpdated", handler: channel })`, granting ONLY `iap:allow-register-listener`. The Channel's onmessage re-dispatches to the onPurchaseUpdated handler. This avoids needing the pub(crate) Rust registry. The "storekit://updated" event name stays as the seam's stable contract: tauri.ts maps the plugin's "purchaseUpdated" channel messages onto the existing onPurchaseUpdated subscriber (no Rust emit needed). NOTE the planner's preferred Rust-emit path is blocked by pub(crate) visibility — use the JS-Channel path below.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| webview → plugin IPC (register_listener) | The webview can register a listener channel; the broad purchase/restore IPC must stay closed to it |
| plugin transaction channel → refreshEntitlements | An update event re-runs the gate; a spoofed event could only TRIGGER a re-read (the read itself re-verifies via the Rust core), not inject a grant |
| boot read → Apple StoreKit | A boot that called AppStore.sync would leak an unwanted Apple-ID auth prompt |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-05 | Elevation of Privilege | webview reaching raw purchase/restore IPC via the listener capability | mitigate | Grant ONLY `iap:allow-register-listener` (one command); `iap:default` and the purchase/restore/acknowledge/consume permissions are NOT granted (Phase-26 §SECURITY CORRECTION). Asserted: grep of the capability file finds no iap:default/allow-purchase/allow-restore; the binary ACL carries only the listener grant. |
| T-28-06 | Spoofing | a forged storekit/purchaseUpdated event injecting Pro | mitigate | The event carries NO entitlement payload — the handler ignores message data and only RE-RUNS refreshEntitlements(), which re-reads iap.currentEntitlements() through the Rust fail-closed core (JWS-verified, intersect_pro). A spoofed event can at most cause a redundant re-read, never a grant. |
| T-28-07 | Information Disclosure | a silent Apple-ID prompt at boot | mitigate | The boot listener calls neither restore() nor AppStore.sync; boot Pro comes from the passive iap.currentEntitlements() local-cache read (D-08). Unit-tested: restore spy 0 calls (Test 6). Restore is the explicit-button-only sync (Plan 03). |
| T-28-08 | Tampering | the drop-write clobbering the prefs blob (prefs-blob-single-writer) | mitigate | The licenseDropNoticeAck write routes through the shared usePreferences module singleton, never a second snapshot — so it folds into the same in-flight blob the hooks read (memory prefs-blob-single-writer). |
| T-28-09 | Denial of Service | the direct build regressing by mounting the iap listener | mitigate | The boot mount is behind `if (IS_APPSTORE)` (build-time constant, tree-shaken from the direct bundle); the capability/plugin are appstore-feature-gated. Direct build mounts nothing. |
