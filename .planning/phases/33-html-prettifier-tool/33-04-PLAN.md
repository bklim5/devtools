<engine_error_facts>
Empirically verified (2026-07-01) against the vendored Prettier 3.8.3 with the EXACT [html, babel, estree, postcss] matrix + `optionsFrom()` (`src/lib/format/prettier.ts`) and `minifyHtml`/`minifyScript` (esbuild, `src/lib/format/minify.ts`) — the two D-11 error categories live on DIFFERENT engine paths:
- MALFORMED-HTML (structure error, Prettify): `formatHtml("<div><span>hi</div>")` THROWS `Unexpected closing tag "div"` at loc (1:14) → surfaces as a `line 1: …` calm error. NOT auto-recovered.
- BAD-EMBEDDED-`<script>` (code error, Minify): `minifyHtml("<script>function(</script>")` runs the body through esbuild, which throws a JS syntax error → surfaces as `<script> block: …` with a line:col.
- CAVEAT (why the split is required): a broken embedded `<script>` does NOT error under `formatHtml` — Prettier's embedded formatting is BEST-EFFORT and leaves the raw script rather than throwing (e.g. `<script>const x=</script>` and `<script>function(</script>` are BOTH ACCEPTED by `formatHtml`). So the embedded-code category MUST be proven via Minify/esbuild, and the HTML-structure category via Prettify/html-parser. Do NOT assert a Prettify error on a broken embedded script (the html parser accepts it — the test would assert the wrong thing).
