## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build env (VITE_CHANNEL + cargo flags) → shipped bundle | A desync between the frontend channel constant and the native build flags would ship a half-variant (e.g. store UI with a live updater, or direct UI in a sandboxed build). |
| committed overlay → base config | The 13.0 bump and sandbox entitlements must stay scoped to the overlay; a leak onto the base would silently raise the direct channel's min-version / break Developer-ID signing. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-04 | Tampering | half-variant (channel/flag desync) | mitigate | VITE_CHANNEL and the cargo flags are bound in ONE package.json script (D-08); there is no second command that sets one without the other. The grep on `scripts['tauri:build:appstore']` proves the binding. |
| T-27-05 | Tampering | 13.0 leaking onto base config | mitigate | The 13.0 bump lives ONLY in the overlay; acceptance asserts `grep '13.0' tauri.conf.json` == 0 and `git diff --stat tauri.conf.json` is empty (base byte-unchanged). |
| T-27-06 | Information disclosure | appstore-only branches in direct bundle | mitigate | `IS_APPSTORE` mirrors `import.meta.env.DEV` — Vite inlines it as a static boolean, so the direct bundle (`VITE_CHANNEL` unset → `false`) tree-shakes every `if (IS_APPSTORE)` branch; this is the seam Phase 28 relies on to keep the store License pane out of the direct build. |
</threat_model>
