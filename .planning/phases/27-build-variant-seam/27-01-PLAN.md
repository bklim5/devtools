<objective>
Layer 1 of the build-variant seam: an umbrella `direct` Cargo feature (default-enabled) that carries the direct-only native deps — the auto-updater and the launch-at-login autostart plugin — so the appstore command (`--no-default-features --features appstore`) compiles them OUT entirely.

Purpose: Cargo features are ADDITIVE — you cannot subtract a dep by adding a feature. The only way to drop updater + autostart from the appstore bundle is to move them behind a `default`-enabled feature and have the appstore build pass `--no-default-features`. This is the compile-out mechanism for MAS-BUILD-03 (Criterion 3); the direct DMG channel keeps both plugins exactly as today (D-05).

Output: A gated `Cargo.toml` + `lib.rs` where `cargo tree --no-default-features --features appstore | grep -E 'updater|autostart'` is empty, while the default `cargo build` is byte-identical in plugin behavior to today.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build invocation → shipped bundle | The cargo feature flags decide which native code links into a user-facing artifact; a wrong flag ships a non-compliant App Store binary (Apple rejects self-updating apps). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-01 | Tampering | Cargo `[features]` block | mitigate | `direct` is `default`-enabled, so a forgetful `cargo build` (no flags) still produces the FULL direct binary — failing safe toward the already-shipped channel, never accidentally toward a broken store binary. The appstore path requires the explicit `--no-default-features --features appstore` (verified by Plan 03's script asserting the cargo tree). |
| T-27-02 | Information disclosure | updater pubkey / endpoints in store binary | mitigate | Compiling the updater crate OUT removes the plugin + its endpoint config from the appstore binary; `cargo tree --no-default-features --features appstore | grep updater` empty is the verifiable proof. No accept/transfer — the crate is fully excluded. |
| T-27-03 | Elevation of privilege | autostart LaunchAgent under sandbox | mitigate | The sandbox-incompatible LaunchAgent writer is compiled out of the store build (no runtime `MissingEntitlement`, no orphaned plist writer). Direct build retains it via the `direct` gate. |
