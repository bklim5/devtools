**1. `infra/keygen/backup.sh`** (mode 755) — the nightly pipeline.

Config resolution (in this order, all overridable for testing):
- `BACKUP_ENV="${BACKUP_ENV:-${XDG_CONFIG_HOME:-$HOME/.config}/devtools-backup/backup.env}"`
- Refuse to run if `$BACKUP_ENV` is missing OR its mode is not `600`
  (`stat -c %a`) — fail closed on a world-readable secret file.
- `set -a; source "$BACKUP_ENV"; set +a`, then require:
  `RCLONE_CONFIG_R2_ACCESS_KEY_ID`, `RCLONE_CONFIG_R2_SECRET_ACCESS_KEY`,
  `RCLONE_CONFIG_R2_ENDPOINT`, `BACKUP_BUCKET`, `BACKUP_GPG_PASSPHRASE_FILE`
  (via `: "${VAR:?...}"`). Optional: `BACKUP_PREFIX` (default `keygen-ce`),
  `HEALTHCHECK_PING_URL`, `BACKUP_RETENTION_BACKSTOP_DAYS` (default `40`),
  `COMPOSE_FILE` (default `$SCRIPT_DIR/compose.yaml`).
- Also require the passphrase file exists and is mode 600.

Modes (argument parsing like release-seat.sh):
- default (no args): run one backup cycle.
- `--install-cron`: idempotently rewrite a managed crontab block and exit.
- `--list`: `rclone lsl` the remote prefix (newest last) and exit — this is the
  RUNBOOK's "are backups actually landing?" command, reusing the loaded creds so the
  human never re-exports them.
- `-h|--help`: usage.

Backup cycle, in order:
1. `TS="$(date -u +%Y%m%dT%H%M%SZ)"`; `STAMP` name
   `${BACKUP_PREFIX}/keygen-${TS}.sql.gz.gpg`.
2. `umask 077`; `WORK="$(mktemp -d "${TMPDIR:-/tmp}/devtools-backup.XXXXXX")"`;
   `trap 'rm -rf "$WORK"' EXIT INT TERM` — the PLAINTEXT dump must never survive the
   run and must never be group/world readable.
3. Dump the LIVE database READ-ONLY through compose (never `psql -c` writes, never
   `docker restart`):
   `docker compose -f "$COMPOSE_FILE" exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner --no-acl' > "$WORK/dump.sql"`
   (`--no-owner --no-acl` makes the artifact restorable into ANY fresh postgres —
   required for the throwaway restore test and for a rebuilt box.)
4. **Sanity-gate the plaintext BEFORE encrypting** — a silently-empty dump uploaded
   nightly is the classic failure. Require ALL of:
   - `dump.sql` size >= `BACKUP_MIN_BYTES` (default 100000);
   - it contains `CREATE TABLE public.accounts` (or `CREATE TABLE` + `accounts`);
   - it contains a `COPY public.accounts` / INSERT-side data section, i.e.
     `grep -q 'COPY public.accounts'`.
   Any failure => `FATAL` + non-zero exit + failure ping (step 9). Nothing uploads.
5. `gzip -9 -c "$WORK/dump.sql" > "$WORK/dump.sql.gz"`.
6. Encrypt with a modern symmetric profile, batch-safe for gpg 2.4:
   `gpg --batch --yes --no-tty --pinentry-mode loopback --passphrase-file "$BACKUP_GPG_PASSPHRASE_FILE" --symmetric --cipher-algo AES256 --s2k-mode 3 --s2k-digest-algo SHA512 --s2k-count 65011712 -o "$WORK/backup.gpg" "$WORK/dump.sql.gz"`.
   Then **round-trip locally before uploading**: decrypt to `/dev/null` (same
   passphrase file) and `gunzip -t` the result — proves the artifact is readable with
   the passphrase the box holds, before it becomes the only copy.
7. Record `sha256sum` of the encrypted artifact into the log line.
8. Upload: `rclone copyto "$WORK/backup.gpg" "r2:${BACKUP_BUCKET}/${STAMP}"`
   with `RCLONE_CONFIG_R2_TYPE=s3`, `RCLONE_CONFIG_R2_PROVIDER=Cloudflare`,
   `RCLONE_CONFIG_R2_NO_CHECK_BUCKET=true`, `RCLONE_CONFIG_R2_ACL=private`
   exported by the script (the two keys + endpoint come from `backup.env`).
   Then VERIFY the object landed: `rclone lsjson "r2:${BACKUP_BUCKET}/${STAMP}"` and
   assert the remote size equals the local size. Upload-without-verify is not done.
9. Retention backstop: `rclone delete --min-age "${BACKUP_RETENTION_BACKSTOP_DAYS}d" "r2:${BACKUP_BUCKET}/${BACKUP_PREFIX}"`
   (default 40d — deliberately WIDER than the 30-day R2 lifecycle rule so the
   lifecycle rule stays primary and the script never races it).
10. Logging + alerting: append one structured line per run to
    `${XDG_STATE_HOME:-$HOME/.local/state}/devtools-backup/backup.log`
    (`ts=... status=ok|fail bytes=... sha256=... object=...`), then truncate the log
    to its last 2000 lines. If `HEALTHCHECK_PING_URL` is set: `curl -fsS -m 10` the
    `/start` endpoint at the top of the run, the bare URL on success, and
    `${HEALTHCHECK_PING_URL}/fail` with the last log lines as the POST body on
    failure (via an `ERR`/`EXIT` trap so ANY failing step reports). If it is unset,
    skip pings silently — the log + `--list` is the documented floor.
    **Executor discretion (pre-approved):** healthchecks.io wiring is optional; if
    the human supplies no URL at the checkpoint, ship the log-only path and say so
    in the RUNBOOK. Do not block on it.

`--install-cron` writes an idempotent managed block (strip the old block by markers,

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live postgres -> dump artifact | The dump contains the account's **Ed25519 private key**, `secret_key`, and every license/machine record — the crown jewels of the licensing system. |
| box -> Cloudflare R2 (public internet) | The artifact leaves the trusted host and lands with a third party who is NOT the compute vendor (deliberate vendor separation from Hetzner). |
| R2 API token -> bucket | A leaked token grants read/write over the backup history. |
| encrypted artifact -> restore host | Anyone with the object AND the passphrase can reconstruct the signing key. |
| dump plaintext -> box filesystem/other local users | Transient plaintext on disk during the pipeline. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-Q-01 | Information disclosure | dump artifact at rest in R2 (contains the Ed25519 private key) | mitigate | GPG **symmetric AES-256** (`--s2k-mode 3 --s2k-digest-algo SHA512 --s2k-count 65011712`) applied ON THE BOX before upload; the plaintext never crosses the network. The passphrase lives ONLY in `~/.config/devtools-backup/gpg.pass` (600) + the owner's password manager — never in R2, the repo, argv, or chat. |
| T-Q-02 | Information disclosure | transient plaintext dump on the box filesystem | mitigate | `umask 077` + `mktemp -d` private work dir + `trap ... EXIT INT TERM` cleanup; nothing is written to a shared/predictable path; the pipeline never writes plaintext under `infra/keygen/` (which `deploy.sh` rsyncs). |
| T-Q-03 | Information disclosure | secrets leaking into git / shell history / chat | mitigate | Real secrets live at `~/.config/devtools-backup/` — OUTSIDE both the repo and `deploy.sh`'s rsync path; only a `.example` template is committed; `.gitignore` block catches stray copies; the checkpoint mandates the `cat > file` + Ctrl-D pattern (pasted stdin is not recorded in bash history) and forbids `echo`/`export` of any value; `backup.sh` refuses to run if the env or passphrase file is not mode 600 (fail closed). |
| T-Q-04 | Tampering | R2 API token abused to overwrite/replace backups | mitigate (partial) | Token scoped to **Object Read & Write on a single bucket** (no account-wide access, no bucket-delete). Objects are write-once per timestamped name (`copyto` to a unique `keygen-<ts>` key), so a normal run never overwrites history. Residual risk accepted: a stolen box token could poison future objects — detection relies on the restore drill, not on immutability (R2 object-lock/versioning is a documented future upgrade, not required at this value/threat level). |
| T-Q-05 | Tampering / Destruction | restore accidentally run against the LIVE database (`pg_dump --clean` emits `DROP ... IF EXISTS`) | mitigate | `restore-test.sh` accepts **no target-database argument at all**; it constructs its own throwaway `postgres:17.5` container with a random password, no ports, no volume, and a fixed `keygen-restore-test-$$` name, plus an explicit guard refusing any name matching the live compose postgres. Live access in both scripts is `pg_dump` + read-only `SELECT` only; no restarts, no `deploy.sh`. |
| T-Q-06 | Denial of service | disk fill / OOM on the 38 GB, 4 GB-RAM CX23 during dump | mitigate | DB is 13 MB (probed), staged artifact is single-digit MB; `mktemp -d` + trap cleanup guarantees no accumulation; no `docker build`; the log is truncated to 2000 lines each run; restore test uses an ephemeral container with no volume. |
| T-Q-07 | Denial of service (silent) | "successful" backups that are empty/corrupt — the classic backup failure | mitigate | Pre-encryption gate: minimum byte size + `CREATE TABLE ... accounts` + `COPY public.accounts` sentinels; post-encryption **local decrypt + `gunzip -t` round-trip** before upload; post-upload remote-size equality check; and a full **restore-and-compare-vs-live** drill (Task 3, documented as monthly). |
| T-Q-08 | Repudiation / undetected failure | a cron backup that silently stops running | mitigate | Structured `status=ok\|fail` log with sha256 per run; optional healthchecks.io `/start` + success + `/fail` pings (dead-man's switch catches "cron stopped firing", which a log alone cannot); `backup.sh --list` documented in the RUNBOOK as the manual check. Executor may ship log-only if the human supplies no ping URL. |
| T-Q-09 | Elevation of privilege | scripts run as a `docker`-group user (root-equivalent) with passwordless sudo | accept | Pre-existing box posture (unchanged by this plan); scripts are 755 and take no untrusted input — the only arguments are `--install-cron`/`--list`/`--object`, and no secret is ever accepted from argv. `sudo` is used ONCE, for `apt-get install rclone`, and never inside the cron path. |
| T-Q-10 | Spoofing | MITM on the upload to R2 | accept | `rclone` speaks TLS to the R2 S3 endpoint using the OS trust store (never `--no-check-certificate`), and the payload is already end-to-end encrypted, so a successful MITM yields ciphertext only. |
